# v0.4 平衡模拟与校准

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.1（含校准） |
| 日期 | 2026-10-10 |
| 脚本 | [`tools/balance-sim.mjs`](../tools/balance-sim.mjs)（`node tools/balance-sim.mjs [--debug]`） |
| 性质 | 估算，非精确值；用于判断节奏目标是否合理 |

## 1. 方法

无头（Node）事件驱动模拟，复用正式 sim 模块：贪心自动购买（能研就研、MAX ALL 生成器；解锁第二阶段前不买晶体升级以攒到 100 晶体），自适应时间步推进到「下一次可购买」。

## 2. 校准前后对比

| 指标 | 校准前 | 校准后 |
|---|---|---|
| 首次触顶（可穿梭） | 5.0 min | **5.0 min**（不变） |
| 第二阶段解锁（持有 100 晶体） | 1.60 h（19 次穿梭） | **1.60 h**（不变） |
| 各层维度折叠 | **≈ 0（瞬时连锁）** | **约 1–7 分钟/层** |
| 第二阶段总时长 | ≈ 0 | **约 31 分钟** |

## 3. 根因

第一阶段末的**绝对产能**（~1e63/game-sec）叠加**时间速率乘子**（解锁后买满速率升级可达 ~1e16），使单次时间步就能跨越 1e20 量级的质能差；且折叠成本仅取前置上限的 ~1e-9，`de_compress`/`de_cap` 的产出加成又让产能反超上限。结果每层折叠在开始前就已可购买。

## 4. 已应用的调整（`config/*.json`）

1. **首层折叠放大**：维度折叠 I 的 `cap_mult` 由 ×1e20 改为 **×1e28**，把「上限/产能」比一次性抬到目标量级；其余层仍 ×1e20（与超维计算同步）。
2. **成本贴近上限**：超维计算成本 = 前置上限的 **50%**；维度折叠成本 = **90%**（此前约 1%~0.0000001%）。迫使「填满上限」重新成为可见的等待。
3. **速率封顶**：`time.rateMultiplierCap` 由 1e30 降至 **1e11**，避免解锁后买满速率升级导致游戏时间瞬间飞过（第一阶段 5 分钟不受影响）。
4. **第二阶段速率技术降档**：因果加速 ×100/×1000/×1e4/×1e5 → 各 **×2**；`dimensional_echo` ×1e5 → **×2**。
5. **暗能量技术改为非产出**：`de_compress` → 穿梭晶体 ×2，`de_cap` → 时间速率 ×2（不再提供全产出加成，避免产能反超上限）。

## 5. 逐层结果（校准后，`--debug`）

| 层 | 累计物理时间 | 本层耗时 |
|---|---|---|
| 维度折叠 I | 1.60 h | ≈ 0（解锁时已在上限） |
| 维度折叠 II | 1.72 h | ~7.2 min |
| 维度折叠 III | 1.81 h | ~5.4 min |
| 维度折叠 IV | 1.87 h | ~3.6 min |
| 维度折叠 V–XII | 1.92 → 2.12 h | 各 ~1–3 min |

后期层略快（速率与成就乘子随进度增长），符合增量游戏的加速手感。整体：**单局 ≈ 5 分钟；第二阶段 ≈ 31 分钟**。

## 6. 局限

- 贪心策略与人工节奏、离线收益、挑战不尽相同；结论用于定性判断。
- 若需更均匀的每层耗时，可进一步微调「超维计算成本比 / 速率上限」，同样是改 config 后重跑本脚本。
