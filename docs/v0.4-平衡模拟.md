# v0.4 平衡模拟（初版结论）

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 日期 | 2026-10-10 |
| 脚本 | [`tools/balance-sim.mjs`](../tools/balance-sim.mjs)（`node tools/balance-sim.mjs`） |
| 性质 | 估算，非精确值；用于判断节奏目标是否合理 |

## 1. 方法

无头（Node）事件驱动模拟，复用正式 sim 模块：

- 贪心自动购买：能研就研、MAX ALL 生成器；**解锁第二阶段前不买晶体升级**（以便攒到 100 晶体触发解锁），解锁后再买。
- 自适应时间步：推进到「下一次可购买」所需的最短游戏时间。
- 记录：首次触顶（可穿梭）、第二阶段解锁、各层维度折叠的物理时间。

## 2. 结果（单次运行）

| 里程碑 | 物理时间 |
|---|---|
| 首次触顶（可穿梭） | **5.0 min** ✅ |
| 第二阶段解锁（持有 100 晶体，19 次穿梭） | **1.60 h** |
| 维度折叠 I ~ XI、奇点折叠（12 层） | **≈ 1.60 h（解锁瞬间全部完成）** |

## 3. 结论

1. **第一阶段节奏符合设计**：首次触顶 5.0 分钟，与数值模型目标一致。
2. **「持有 100 晶体」门槛合理**：约 1.6 小时、19 次穿梭达到，作为第二阶段门槛可接受。
3. **⚠️ 第二阶段几乎没有摩擦**：解锁后 12 层折叠在**几乎零物理时间**内连锁完成，远快于「每层 2–5 分钟」的目标。

### 原因分析

- 折叠成本仅取「上一档上限 × 1e-1~1e-3」，而第一阶段末的绝对产能已高达 ~1e63（技术 ×5e56 + 升级/挑战/成就），叠加时间速率乘子后，单次 step 就能跨越 1e20 量级的质能差。
- 每层同时给「生产 ×1e20」与「上限 ×1e20」，二者同步膨胀，使每层所需时间被压成常数（且极小）。

## 4. 建议调整方向（待下一轮校准）

择一或组合：

1. **拉开成本/上限比**：折叠成本改为「**当前上限 × 1e15**」量级，强制先接近上限再折叠，让「填满上限」重新成为可见的等待。
2. **降低每层生产跳变**：超维计算 ×1e20 → 例如 ×1e10，使新上限需要更多积累时间。
3. **限制时间速率**：下调 `rateMultiplierCap`（现 1e30），减少「瞬间跨越数量级」。
4. **给折叠加前置/冷却**：例如每层需先达成某个质能里程碑。

> 迭代方式：改 `config/*.json` 后重跑 `node tools/balance-sim.mjs`，观察各层时间是否落在 2–5 分钟区间。

## 5. 局限

- 模拟为贪心策略，未模拟人工节奏、离线收益与挑战；
- 大数在 rate 上限附近时，物理时间步极小，折叠时间戳可能被压缩；
- 结论用于**定性**判断（第二阶段过快），精确数值需结合实机试玩。
