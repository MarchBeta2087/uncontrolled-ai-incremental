## 2. 数值层设计

### 2.1 Num 适配器 API

封装 MegotaNum，逻辑层只认这一组接口；换库时只改本文件：

```
Num.parse(x) / Num.fromJSON / Num.toJSON
add, sub, mul, div, pow, cmp, max, min, log10, floor
Num.format(x, mode)     // 显示格式化（见 2.3）
Num.isFinite(x), Num.isNaN(x)
```

### 2.2 不变式

- 所有资源量、成本、产量一律为 Num（MegotaNum 实例），禁止混用原生 Number 参与运算。
- 比较、阈值判断必须走 `cmp`，不得依赖 `>` 隐式转换。
- 游戏内时间累计量为 Num（见 §3）；仅物理秒差值（tick 间隔、离线时长）用 float64。

### 2.3 格式化档位

显示层优先级：普通记数 → 科学计数（e 记法）→ MegotaNum 内置字符串（{10,x,y,z} 族）。切换阈值与样式放 `balance.json`，保证全局一致。

## 3. 时间系统设计

### 3.1 模型

- 状态只存一个量：`gameSecondsElapsed`（**Num 实例**，自 UTC 2028-01-01 0:00 起累计的游戏内秒数）。采用 Num 而非 float64 的原因：年份显示允许走到 MegotaNum 量级（需求 §5.1），float64 在累计秒数约 2^53（≈**2.85 亿年**）处即丢整数精度——恰好卡在科学记数法档（10⁸ 年）门槛附近，撑不到 MegotaNum 档的设计寿命。
- **初始速率 1 物理秒 = 10000 游戏秒**；当前速率 = 初始值 × 速率乘积（科技、升级、挑战皆可贡献乘子；乘子用 Num，设软上限防天文数字运算拖慢 tick）。
- 每 tick：`gameSecondsElapsed = add(gameSecondsElapsed, mul(Num(dt_real), currentRate))`。

### 3.2 分级显示

先算游戏内年份：`years = div(gameSecondsElapsed, 31557600)`（1 儒略年 = 31,557,600 秒），`Y = 2028 + years`。按需求 §5.1 分级：

| 条件 | 显示 |
|---|---|
| Y < 10⁶ | 完整 UTC 日期时间（年-月-日 时:分:秒），走原生 Date 格式化（此时 gameSecondsElapsed 必在 float64 安全整数范围内，先 `toNumber()` 再格式化） |
| 10⁶ ≤ Y < 10⁸ | 仅显示整数年份（`floor` 后经 toNumber 转换，范围安全） |
| Y ≥ 10⁸ | 科学记数法（如 `3.2×10⁸ 年`），由 Num.format 的 e 记法档位处理 |
| Y 超 float64 | MegotaNum 记法（如 `{10,10,2} 年`），由 Num.format 的 BAN 档位处理 |

切换阈值放 `balance.json`（默认 10⁶ / 10⁸，可调）。UI 恒定标注"游戏内时间"。

### 3.3 离线结算

存档记录 `lastRealTimestamp`。启动时：先按存档时的速率结算离线收益（`Δt_real × rate_offline`），再进入正常循环。离线速率是否打折扣，由 `balance.json` 的参数控制（默认 100%，M1 推演后定）。

### 3.4 穿梭回卷

穿梭时：`gameSecondsElapsed = 0`（回到 2028-01-01 0:00），周目数 +1，速率乘子按穿梭结算结果重置/重算。

## 4. 模拟引擎

### 4.1 主循环

- 固定步长 100ms（`setInterval` 漂移由 `performance.now()` 差值校正）。
- 每 tick 顺序：结算时间增量 → 各资源生产链结算 → 解锁条件检查 → 成就/碎片触发检查 → 置脏标记。
- 渲染循环独立（requestAnimationFrame 节流至 ~6Hz，仅刷新脏组件）。

### 4.2 生产链结算

资源产出为 `产量 = 基础产量 × 数量 × 科技乘子 × 升级乘子 × 周目乘子` 的连乘（全部为 Num）。订单结算：先产出后消耗，避免死锁；消耗不足时按产能比例缩放出产（规则放 balance.json）。

## 5. 内容配置（JSON Schema 要点）

### 5.1 resources.json

```
{
  "id": "compute",
  "name": "算力",
  "baseProduction": 1,          // 基础产量（Num 可解析）
  "cost": {...},                // 购买成本曲线（基值 + 增长指数）
  "unlocks": ["tech_ai_core"],  // 解锁科技
  "tier": 1                     // 阶段：1 资金/算力 → 4 宇宙质能
}
```

### 5.2 techs.json

```
{
  "id": "dyson_lattice",
  "name": "戴森格点",
  "cost": {...},                // 一次性成本
  "requires": ["stellar_industry"],
  "effects": [                  // 效果声明式描述，引擎解析执行
    {"type": "mult", "target": "energy_production", "value": 50},
    {"type": "rate_mult", "value": 2}     // 时间速率乘子示例
  ],
  "tier": 3
}
```

效果类型在引擎中注册为有限枚举，配置加载时校验合法性——**配置里不允许出现任意代码**。

### 5.3 upgrades.json（时间晶体升级树）

```
{
  "id": "causal_residue_1",
  "name": "因果残响 I",
  "cost": {"currency": "time_crystal", "amount": 1},
  "effects": [{"type": "mult", "target": "all_production", "value": 2}],
  "requires": []
}
```

### 5.4 fragments.json（叙事碎片）

```
{
  "id": "frag_audit_log",
  "week": 3,                    // 第 3 周目起可掉落
  "condition": "prestige_count >= 3",
  "text": "……（短文本日志体，全部重写，不照搬参考故事原句）"
}
```

加载时统一校验：id 唯一、requires 无环、数值可解析为 Num、effect 类型已注册。

## 6. 时空穿梭模块

### 6.1 触发

终局资源（宇宙质能）达到触顶阈值（balance.json）。触达时弹出穿梭确认面板，展示结算预览（见 6.2），确认后执行。

### 6.2 结算公式

```
时间晶体 = floor( F(本轮宇宙消耗度, 研发深度, 周目数) )
```

F 的具体形态在 M1 推演中确定，此处只定结构：**收益须单调、可解释、有软上限**（防止后期周目收益爆炸摧毁升级树定价）。首次穿梭产出校准到"恰好购买 1~2 个一级升级"（需求 §4.3）。

### 6.3 重置执行顺序

结算晶体 → 保存元进度（周目、成就、碎片、晶体、核心理论）→ 清空周目内状态（资源、建筑、科技、时间）→ 应用穿梭结算带来的永久效果 → 回到 2028-01-01 0:00 → 播放回卷动画与结算面板。

**顺序不可乱**：必须先取元进度快照再清空，任何异常不得使玩家损失元进度（关键区 try/catch + 结算前自动备份存档）。

## 7. 存档系统

### 7.1 结构

```
{
  "schemaVersion": 1,
  "meta": {"createdAt": ..., "lastSaveAt": ..., "prestigeCount": n},
  "time": {"gameSecondsElapsed": <Num>, "rateMultipliers": {...}},
  "run": {"resources": {...}, "techs": [...], "buildings": {...}},
  "metaProgress": {"timeCrystals": {...}, "upgrades": [...], "achievements": [...], "fragments": [...]},
  "theories": [...]             // 穿梭后保留的核心理论
}
```

- Num 一律序列化为 MegotaNum JSON（数组+层结构），不序列化格式化字符串。
- 自动存档：每 30 秒 + 页面隐藏时 + 穿梭结算前。

### 7.2 迁移

按 `schemaVersion` 链式执行迁移函数 `migrate_1to2`、`migrate_2to3`……，启动加载时跑到当前版本；未知更高版本 → 拒绝加载并提示（防止新旧版本互踩）。

### 7.3 导出/导入

导出为带版本头的 JSON 文件下载；导入时同样走迁移链并校验。导出文件不含任何个人数据（单机游戏本就无此问题，写进文档以绝后患）。

## 8. 界面设计

### 8.1 平台判定

```
isMobile = matchMedia('(pointer: coarse)').matches || innerWidth < 768
```

结果决定加载哪套外壳样式与布局；共用组件（按钮、面板、进度条）在 core.css，皮肤差异只覆盖 chrome。

### 8.2 桌面外壳（MVP）

- 顶部：标题栏（仿 Windows 窗口）+ 游戏内 UTC 时间戳 + 周目数。
- 主体：多"窗口"布局——资源窗口、研发窗口（科技树）、扩张窗口；窗口可最小化到任务栏。
- 底部：任务栏式导航 + 存档/设置入口。
- 穿梭触发时：全屏"回卷"动画（时间倒流的视觉）+ 结算面板（模态窗口）。

### 8.3 移动端外壳（M3）

- 底部 Tab 导航：资源 / 研发 / 扩张 / 元（晶体与升级）。
- 卡片式列表，触控目标 ≥44px。
- 穿梭动画降级为全屏渐变 + 结算页（移动端不做复杂粒子，保帧率）。

### 8.4 渲染约束

- 数值文本渲染节流（同帧内相同组件只格式化一次）。
- 脏检查：引擎置脏 → 渲染只刷脏组件；长列表（科技树）做可见区渲染预留。

## 9. 成就与碎片

- 成就：条件声明式（`{"type": "resource_ge", "target": "compute", "value": "1e100"}`），引擎统一轮询；展示为徽章墙。
- 碎片（需求 §8.4）：达成条件后进入碎片收集册；集齐为终局条件之一。文案全部原创重写，风格为短文本日志体（审计日志、循环残响、伊甸环目击记录等），与机制设定一一对应。

## 10. 错误处理与边界

| 场景 | 行为 |
|---|---|
| MegotaNum 运算产生 NaN / Infinity | 数值层拦截，记 console 告警，该资源回退为上次合法值 |
| localStorage 不可用/超限 | 降级为仅内存运行 + 提示使用导出备份 |
| 存档校验失败 | 拒绝加载，提供"导出损坏档"按钮供诊断，不得静默覆盖 |
| 穿梭结算中断（异常） | 回滚到穿梭前自动备份 |
| 系统时间被玩家回拨 | 离线结算用 `max(0, now - lastSave)`，负值按 0 处理 |
| gameSecondsElapsed 运算产生 NaN | 时间轴冻结在本次合法值，UI 显示"时间轴异常"并告警，不得让负数/NaN 年份流到显示层 |

## 11. 配置驱动与平衡

- **一切可调参数进 `config/balance.json`**：膨胀基值、成本指数、穿梭结算系数、晶体定价、时间速率乘子上限。调平衡 = 改 JSON + 跑回归，不改代码。
- M1 产出：膨胀曲线文档（预期触顶所需游戏内时间 vs 周目数的表格）+ balance.json 初值。

## 12. 测试要点

1. 配置 schema 校验全绿（CI 可跑，纯 Node）。
2. 关键公式快照回归（产出链、成本曲线、穿梭结算、晶体定价）。
3. 存档迁移链：构造 v1 存档 → 加载 → 校验字段完整。
4. 穿梭闭环手测清单：触顶 → 预览 → 确认 → 元进度无损 → 时间归零 → 升级可购。
5. 双外壳渲染冒烟：同一份逻辑状态在两套皮肤下数值一致。
6. 离线结算：模拟 8 小时离线，收益误差 <1 tick。
7. 时间分级显示：构造 gameSecondsElapsed = 10⁶ 年、10⁸ 年、10²⁰ 年样本，逐级验证显示切换正确且无精度错乱。
