## 1. 许可证兼容矩阵

项目素材统一以 **CC BY-SA 4.0** 发布（代码 GPL-3.0-or-later、字体 SIL OFL 1.1 单独授权）。因此引入的素材许可证必须能**并入 CC BY-SA 4.0 作品**。

> **重要**：这里说的是「**兼容 CC BY-SA 4.0**」——它**包括 CC BY-SA 4.0 本身，但不限于它**。下表所有 ✅ 项都合格。

| 素材许可证 | 能否引入 | 要求 | 说明 |
|---|---|---|---|
| CC0（公有领域捐献） | ✅ 优先 | 无 | 最省事，直接可用 |
| Public Domain（公有领域，PDM） | ✅ | 无 | 确认来源国家公有领域判定 |
| **CC BY 4.0** | ✅ | 署名作者 | 与 BY-SA 4.0 **单向兼容**：可改编后以 BY-SA 4.0 发布 |
| **CC BY-SA 4.0** | ✅ 首选 | 署名 + 相同方式共享 | 与项目素材许可完全一致 |
| CC BY-SA 3.0（标注 "3.0 or later"） | ⚠️ 逐案 | 署名 + 相同方式共享 | 需原作品明确标注 "or later" 才能升级到 4.0；否则先确认 |
| 双重许可（如 "CC BY 4.0 / MIT"） | ✅ | 择一遵守 | 选 CC BY 4.0 分支遵守 |
| SIL OFL 1.1（字体） | ✅ 仅字体 | 附 OFL 文本 + 遵守保留字体名 | 见 §4 |
| **带额外 EULA 限制的「伪 CC」** | ❌ 禁止 | — | 在 CC 协议外附加「禁止再授权 / 禁止独立再分发」等，见 §6 |
| CC BY-NC / BY-NC-SA | ❌ 禁止 | — | "非商业"限制与 GPL 允许商业使用冲突 |
| CC BY-ND | ❌ 禁止 | — | "禁止演绎"，游戏素材几乎都要裁剪/调色/缩放 |
| 无许可证声明 / 版权不明 | ❌ 禁止 | — | 默认"保留所有权利"，不可用 |
| 专有 / 付费素材 | ❌ 禁止 | — | 除非取得书面授权并入本仓库 |
| 截图他人游戏 / 商业作品 | ❌ 禁止 | — | 侵权风险高 |

**记忆口诀**：`CC0、PDM、BY、BY-SA 可以用；NC、ND、伪 CC、无证、专有不能用。`

## 2. 推荐搜索来源

- **Creative Commons 搜索**：<https://search.creativecommons.org/>
  - 使用要点：搜索后在左侧筛选框勾选许可证（CC0 / BY / BY-SA），并勾选"可修改 / 可商用"。
  - 它聚合 Openverse、Flickr、Wikimedia Commons、SoundCloud 等平台，但**最终许可以来源站原页面为准**。
- 其它可选来源（均需回原页核实许可证，且不得属于 §6 黑名单）：
  - Wikimedia Commons（图片/音频，许可证标注清晰）
  - OpenGameArt.org（游戏素材，注意逐条看许可证）
  - Freesound.org（音效，注意非 CC0 条目是否允许商用）
  - Google Fonts / Fontsource（字体，OFL 为主，需下载 OFL 文本）

> ⚠️ 任何聚合站的筛选结果都**不构成法律依据**，必须回到素材原始页面确认许可证后再下载。

## 3. 入库流程（每件素材必做）

```
① 搜索/筛选许可证 → ② 打开原页核实 → ③ 下载 + 记录信息 → ④ 放入 assets/ 对应目录 → ⑤ 登记 ASSETS.md
```

### 3.1 必记信息（缺一不可）

| 字段 | 示例 |
|---|---|
| 文件名（入库后） | `assets/images/starfield-bg.png` |
| 来源 URL | `https://example.com/photos/starfield` |
| 作者（署名名） | `John Doe` |
| 许可证 + URL | `CC BY-SA 4.0 — https://creativecommons.org/licenses/by-sa/4.0/` |
| 获取日期 | `2026-10-10` |
| 是否修改 + 说明 | `裁剪为 1920×1080，压暗 20%`（未修改填"原样"） |

### 3.2 目录结构

```
assets/
├── images/          # 图片素材（CC BY-SA 4.0 兼容）
├── audio/           # 音效/音乐（CC BY-SA 4.0 兼容）
└── fonts/           # 字体（SIL OFL 1.1，附各自 OFL 许可证文本）
```

### 3.3 ASSETS.md 登记格式

在 `ASSETS.md` 中按以下表格逐条登记：

```markdown
| 文件 | 作者 | 来源 | 许可证 | 获取日期 | 修改说明 |
|---|---|---|---|---|---|
| images/starfield-bg.png | John Doe | https://... | CC BY-SA 4.0 | 2026-10-10 | 裁剪+压暗 |
```

## 4. 字体特殊规则（SIL OFL 1.1）

- 字体文件放 `assets/fonts/`，**每个字体附带其 OFL 许可证文本**（如 `assets/fonts/<FontName>/OFL.txt`）。
- **保留字体名（Reserved Font Name）条款**：修改字体后不得沿用原名发布。
  - 若只做"嵌入游戏"（不改字体文件本身），保留原字体名没有问题。
  - 若对字体做了子集化/改字形，必须改名，并在 ASSETS.md 注明"修改自 X，已更名 Y"。

## 5. AI 生成素材的额外要求

- AI 生成素材（图/音/文案）能否用于本项目，取决于**所用工具的授权条款**：部分工具禁止商用或要求署名，需逐工具核实并记录。
- 剧情碎片等文案：必须原创重写，**不得照搬参考底稿或任何现有作品原文**（CONTRIBUTING.md 已明确）。
- 无论来源，AI 生成素材同样登记 ASSETS.md，并注明生成工具与版本。

## 6. 禁用来源黑名单

以下来源**一律禁止**用于本项目。即便它们自称 "Creative Commons"，也因在标准 CC 协议之外附加了限制，导致**无法合法并入 CC BY-SA 4.0 作品**（尤其是无法向你的下游玩家再许可）。

### 6.1 Pixabay（`pixabay.com`）

**判定：禁止。** 原因：

- Pixabay 现在使用的是 **Pixabay Content License，并非任何 CC 协议**（约 2019 年起已弃用 CC0）。
- 该许可**禁止"standalone（独立）"再分发/转售**，且你**无权将其内容再许可（relicense）为 CC BY-SA 4.0**——而本项目要求素材统一以 CC BY-SA 4.0 再分发，这一步在法律上无法完成。
- 内容可能涉及商标、可识别人物等附加权利，来源追踪不透明。

### 6.2 Silverman Sound（`silvermansound.com`）

**判定：禁止。** 原因：

- 其音乐实际为 **CC BY 4.0**，但站点在 CC 之外**附加了自定义 EULA 条款**：禁止再授权（sublicence）、禁止将音乐作为独立音频再分发、禁止注册 Content ID 等。
- 注意：**纯 CC BY 4.0 本身是合格来源**（见 §1）；被禁的是这个**站点/其自定义 EULA**，而不是 "CC BY 4.0" 这个许可证。
- 关键冲突在于「**禁止再授权**」：向玩家分发游戏=向玩家再许可音乐，直接与该条款冲突，也与 CC 协议"可向下游再授权"的本质相悖。

### 6.3 通用判据（凡命中即拒绝）

- 在标准 CC 协议之外附加**禁止再授权（no sublicense）**、**禁止独立再分发**、**禁止演绎**等额外限制的「伪 CC」来源。
- 仅笼统标注 "Creative Commons" 却**不给出具体版本与官方链接**、无法核实的来源。
- 下载/使用需要注册付费墙、且条款与 CC BY-SA 4.0 冲突的来源。

> 发现新的不合格来源，请在 PR 中补充到本节。

## 7. 素材征集

本项目欢迎社区投稿美术、音乐与音效。**你保留署名权**，素材以 **CC BY-SA 4.0** 入库（或兼容许可，见 §1）。

### 7.1 当前需要的素材方向

| 方向 | 说明 | 参考尺寸/格式 |
|---|---|---|
| 背景图 | 星场、星云、宇宙终局氛围（暗色为主，配合像素风 UI） | PNG/WebP，1920×1080 起 |
| UI 图标 | 资源图标（资金/算力/工业/质能）、导航图标 | PNG/SVG，32×32 / 64×64 |
| 音效 | 点击、购买、升级、穿梭、成就解锁 | OGG/MP3，短促 |
| 背景音乐 | 循环 BGM（冷峻/机械/宇宙感），低干扰 | OGG，1–3 分钟可循环 |
| 像素立绘 / 过场 | 结局 / 周目过场的像素插画 | PNG，256×256 起 |

### 7.2 投稿方式

1. 阅读本规则 §1 与 §6，确认授权合格。
2. 在 Issue 中贴出预览 + 来源/作者 + 许可证，或直接提 PR（按 §3 入库并在 `ASSETS.md` 登记）。
3. 若你不确定授权是否合格，先开 Issue 讨论，不要直接下载入库。

> 投稿即表示你同意该素材以 CC BY-SA 4.0（或你指定的、兼容 CC BY-SA 4.0 的许可证）发布。

## 8. 禁止事项清单

1. 下载"版权不明 / 无许可证声明"的素材。
2. 引入 NC、ND 类许可证素材。
3. 使用 Pixabay、Silverman Sound，或任何带额外 EULA 限制的「伪 CC」来源（见 §6）。
4. 截图他人游戏、影视、商业插画当作素材。
5. 把来源站的水印、作者署名信息裁掉后使用（署名是法律义务，不是可选）。
6. 只登记"好看的"，漏登记"顺手用的"小素材（图标、按钮、背景音乐都要登记）。
7. 修改字体后沿用原名。

## 9. PR 检查清单（含素材时必须全部打勾）

- [ ] 每件素材许可证已在原页面核实，属于 CC0 / PDM / CC BY 4.0 / CC BY-SA 4.0（字体为 OFL）。
- [ ] **不来自 §6 黑名单来源**（Pixabay、Silverman Sound 等）。
- [ ] 每件素材的 6 项必记信息完整，已登记进 `ASSETS.md`。
- [ ] 字体已附 OFL 文本；若修改过字体，已改名并注明。
- [ ] 无 NC、ND、伪 CC、无证、专有素材混入。
- [ ] 未使用他人游戏/商业作品截图。
- [ ] 许可证文本文件（如 CC BY-SA 摘要或链接）随素材一并归档（可放 `assets/LICENSES/`）。
