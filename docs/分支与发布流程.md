# 分支与发布流程

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 适用仓库 | <https://github.com/MarchBeta2087/uncontrolled-ai-incremental> |

本项目采用**轻量 Git Flow**：`main` 只放稳定版本，日常开发汇总到 `dev`，任何改动都通过 **Pull Request** 合入。这样 `main` 始终可玩、可部署，也方便回滚。

---

## 1. 分支模型

```
main   ──●────────────●──────────●──→   稳定 / 已发布；GitHub Pages 从这里部署
          \          / ↑ merge PR
           \        /
dev    ────●──●──●──┘                   集成分支；下个版本的汇总
            \   \  ↑ PR
             \   \
feat/*  ──────●───●                     功能分支（fix/*、docs/*、chore/* 同理）
```

| 分支 | 用途 | 谁能直接 push | 来源 | 合并去向 |
|---|---|---|---|---|
| `main` | 稳定/已发布，Pages 部署源 | 无人（仅 PR） | — | — |
| `dev` | 集成分支，下个版本 | 无人（仅 PR） | `main` | `main`（发布时） |
| `feat/*` `fix/*` `docs/*` `chore/*` | 具体改动 | 作者 | `dev` | `dev` |

命名约定：`feat/` 新功能、`fix/` 修 bug、`docs/` 文档、`chore/` 杂务（CI、依赖、格式）、`refactor/` 重构。

## 2. 日常开发流程

```bash
# 1. 同步 dev
git checkout dev
git pull origin dev

# 2. 切出功能分支
git checkout -b feat/phase2-tech

# 3. 开发、提交
git add -A
git commit -m "feat: 第二阶段技术树"

# 4. 推送并开 PR（目标分支选 dev）
git push -u origin feat/phase2-tech
gh pr create --base dev --head feat/phase2-tech
```

外部贡献者请先 **Fork** 仓库，从上游 `dev` 切分支，向上游 `dev` 发起 PR。

PR 合入前必须满足：

- [ ] CI（`ci.yml`）通过：配置校验 + 冒烟/回归测试。
- [ ] 遵守 [CONTRIBUTING.md](../CONTRIBUTING.md) 的开发约定（分层、Num 适配器、内容 JSON 化、balance.json 只调数值）。
- [ ] 若含素材：遵守 [素材与授权规则](素材与授权规则-v1.1.md) 并登记 `ASSETS.md`。
- [ ] 至少一名维护者 review 通过。

合并方式：**Squash merge**（保持 `dev` 历史整洁）。

## 3. 发布流程

版本号遵循 [SemVer](https://semver.org/lang/zh-CN/)。

```bash
# 1. 确保 dev 全部就绪、CI 通过
git checkout dev && git pull origin dev

# 2. 用 PR 把 dev 合入 main（base=main, head=dev），合并方式用 merge commit
gh pr create --base main --head dev --title "release: v0.4.0"

# 3. 合并后打 tag 并推送
git checkout main && git pull origin main
git tag -a v0.4.0 -m "v0.4.0"
git push origin v0.4.0
```

- 合并到 `main` 会**自动触发 GitHub Pages 部署**（`.github/workflows/pages.yml`）。
- 发布同时更新 [CHANGELOG.md](../CHANGELOG.md)，记录 `新增 / 变更 / 修复`。
- `dev` 合入 `main` 后，把 `main` 反向合并回 `dev`（或让 `dev` 快进），保持两线不漂移：

```bash
git checkout dev
git merge origin/main
git push origin dev
```

## 4. 分支保护设置（仓库管理员手动配置）

分支保护**无法由仓库内文件控制**，需在 GitHub 上配置。推荐对 `main` 与 `dev` 都开启：

### GitHub 网页端

1. 进入 **Settings → Branches → Add branch protection rule**。
2. Branch name pattern 填 `main`（再对 `dev` 重复一次）。
3. 勾选：
   - **Require a pull request before merging**
   - **Require status checks to pass before merging** → 选择 `CI / test`
   - **Require conversation resolution before merging**
   - **Do not allow bypassing the above settings**
4. 保存。

### 命令端（需要管理员权限的 token）

```bash
# 注意：gh api 的分支保护接口需要仓库管理员权限；CI 检查名以实际 workflow job 名为准
gh api -X PUT repos/MarchBeta2087/uncontrolled-ai-incremental/branches/main/protection \
  -H "Accept: application/vnd.github+json" \
  -f required_status_checks[strict]=true \
  -f required_status_checks[contexts][]=test \
  -f enforce_admins=true \
  -f required_pull_request_reviews[required_approving_review_count]=0 \
  -f restrictions=
```

> `dev` 可重复上面的接口，把 `.../branches/dev/protection` 即可。

## 5. CI / Pages 行为

| Workflow | 触发 | 说明 |
|---|---|---|
| `ci.yml` | push 到 `main` / `dev`、任意 PR | 跑 `node test/smoke.mjs` |
| `pages.yml` | push 到 `main`、手动 | 部署静态站点到 GitHub Pages |

`dev` 分支**不会**部署到 Pages（保持线上为稳定版）。如需 PR 预览站，可后续接入 Cloudflare Pages / Netlify（本仓库暂不配置）。
