## 1. 复现

```bash
node tools/balance-sim.mjs                 # 单宇宙（与 v0.4 相同）
node tools/balance-sim.mjs --multiverse    # 多宇宙：完成 12 折叠后自动跃迁
MAX_UNIVERSES=3 node tools/balance-sim.mjs --multiverse
node tools/balance-sim.mjs --multiverse --debug   # 每次折叠打印质能/上限/产能/速率
```

策略：事件驱动 + 贪心（买满生成器、能研就研、解锁第二阶段后买晶体与跨宇宙升级；完成 12 层折叠即跃迁）。停滞保护：若下一购买需 > 1e15 游戏秒则记录并停止该宇宙。

## 2. 结果（宇宙 1，基准）

| 里程碑 | 物理时间 |
|---|---|
| 首次触顶（可穿梭） | 5.0 min |
| 第二阶段解锁（持有 100 晶体） | 1.60 h |
| 12 层折叠 | 1.60 h → 2.12 h（约 1–7 min/层） |
| **宇宙 1 完成（奇点折叠）** | **2.12 h** |

与 v0.4 结论一致（宇宙 1 未受 v0.5 影响）。

## 3. 结果（宇宙 2 / 3，均匀缩放）

v0.5 采用**均匀缩放**：宇宙 N 的上限、产出、第二阶段成本同乘 `universeMult(N) = 10^(308·3^(N−1) − 308)`（U2 = 1e616、U3 = 1e2464）。

| 宇宙 | 结果 |
|---|---|
| 宇宙 2 | 折叠 12/12，耗时 **≈0（<10 游戏秒）** |
| 宇宙 3 | 折叠 12/12，耗时 **≈0** |

后续宇宙在保留**时间晶体升级**与**跨宇宙升级**的情况下，产出远超抬升后的上限，一步跨过全部折叠。

## 4. 结论与建议

- **均匀缩放修复了两个引擎级死结**（均由本模拟发现，见 §5），机制上可玩、可跃迁。
- 但**保留的元进度使后续宇宙过快**，未达设计目标（每宇宙数分钟）。建议之一：
  - 引入按宇宙递增的**难度附加乘子**：`costMult = capMult × difficulty(universe)`，`difficulty` 随宇宙递增；或
  - 采用**更小的上限指数增长**（如每宇宙 +200 而非 ×3）；或
  - 对跨宇宙升级的产出加成设上限。
- 建议专门排一轮平衡（沿用 M1 推演流程），本 PR 先保证机制正确、工具就绪。

## 5. 模拟驱动的设计修正（本 PR 记录）

1. **成本随宇宙缩放但产出不缩放 → 死结**：若第二阶段成本 ×1e616 而产出不变，各宇宙首个第二阶段技术（5e685）在阶段 1 产出（~1e70）下永远买不起。
2. **只抬升上限、不缩放产出 → 无法穿梭**：上限抬到 1e686，阶段 1 产出无法触顶，jump 条件与 prestige 双双卡死。
3. **修正**：**上限 / 产出 / 第二阶段成本三者同步缩放**，使每宇宙相对节奏与宇宙 1 一致；跨宇宙效果在每次穿梭后重放（`main.js` 的 `prestige:done` 处理器调用 `Singularity.applyCrossUniverse()`，模拟器以 `reapplyMeta()` 对齐）。

> 这三条正是 `tools/balance-sim.mjs` 存在的意义：在写死代码前暴露结构性问题。
