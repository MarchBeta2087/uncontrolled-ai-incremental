| 项目 | 内容 |
|---|---|

> **一句话**：v0.4 把本宇宙质能顶到 float64 上限（1.7977e308 J）——「这个宇宙装不下了」。v0.5 把整条第二阶段进程压缩成可重复的单元，向外跃迁到下一宇宙，并引入跨宇宙元货币「奇点种子」与跨宇宙升级树。

---

## 1. 层级与解锁

| 层级 | 动作 | 保留 | 清空 |
|---|---|---|---|
| L1 穿越（Prestige） | 达到当前宇宙上限 | 时间晶体、升级、永久技术、成就、碎片、种子、宇宙编号 | 资源 / 生成器 / 非永久技术 / 时间轴 / 暗能量 |
| **L2 宇宙跃迁（本版新增）** | **当前宇宙第二阶段全部完成** | **奇点种子、跨宇宙升级、时间晶体升级、成就、碎片、统计量** | **资源 / 生成器 / 全部技术（含永久）/ 时间轴 / 暗能量 / 当前时间晶体 / 第二阶段解锁** |

- **跃迁解锁条件**：`Techs.allPhase2Researched()`（35 项第二阶段技术全部研发，即奇点折叠完成）**且** 质能触顶当前宇宙上限。二者同时满足才允许跃迁（与 v0.4 Endgame 触发一致）。
- **跃迁是第三层重置**：照抄 prestige 的纪律——**结算 → 元进度快照 → 清空 → 永久效果重放**，顺序不可乱、快照先于清空。

> **设计裁定（回应 Issue #16 待定问题）**：v0.4 的第二阶段技术带 `permanent: true`，其语义是「跨**穿梭**保留」。宇宙跃迁是更高一层，**会重置这些技术**，让每个宇宙重新走一遍第二阶段（变体）。跨宇宙保留的是**新引入的**「跨宇宙升级」（用奇点种子购买）与既有的时间晶体升级。这就是「已购永久升级保留」的含义。

## 2. 奇点种子（Singularity Seed，新货币）

- **定位**：口袋内衬上写着的名字，在口袋被「造福完成」（首次触顶跃迁）时凝成的结晶。
- **产出**：**首次**从宇宙 N 跃迁时发放 `seedReward(N)`，与记忆碎片同步。
- **公式**（初版）：`seedReward(N) = 2^(N-1)`（U1→1、U2→2、U3→4…，指数递增）。
- **存储**：`metaProgress.singularitySeeds`（Num JSON），跨宇宙永久保留。
- **展示**：标题栏元信息区 + 扩张视图「奇点」面板。

公式在 `config/universes.json` 的 `fallback.seedReward` 中参数化，实装后用平衡模拟校准。

## 3. 每宇宙配置表（`config/universes.json`）

难度递增 = **上限序列变化**（指数乘算），不是平铺产出乘子。

```json
{
  "universes": [
    { "id": 1, "name": "初生宇宙", "capExponent": 308,     "seedReward": "1", "rateMult": "1", "restrictions": [] },
    { "id": 2, "name": "第二口袋", "capExponent": 924,     "seedReward": "2", "rateMult": "1", "restrictions": [] },
    { "id": 3, "name": "第三口袋", "capExponent": 2772,    "seedReward": "4", "rateMult": "0.9", "restrictions": [] }
  ],
  "fallback": { "capExponentBase": 308, "capExponentGrowth": 3, "seedRewardBase": "1", "seedRewardGrowth": "2" },
  "crossUniverseUpgrades": [ /* 见 §4 */ ]
}
```

- **上限指数**：`capExponent(N) = 308 × 3^(N-1)`（U1=308、U2=924、U3=2772…；约第 9 宇宙跨过 1e1000000，衔接 Issue #19）。
- **宇宙上限乘子**：`universeCapMult(N) = 10^(capExponent(N) − 308)`，注册为 `Mults` 的一条 `cap_mult` 来源，故 `getUniverseCap()` 引擎几乎不动。
- **成本同步缩放**：第二阶段技术成本 × `universeCapMult(N)`，保持「上限 / 成本」比例不变，从而每宇宙节奏一致；跨宇宙升级与保留的全局乘子使后续宇宙加速。
- **上限封顶**：`getUniverseCap() = min(baseCap × Π(cap_mult), 10^capExponent(N))`。宇宙 1 的上限即 float64 上限（保持 v0.4 叙事），宇宙 ≥2 允许越过 float64（MegotaNum 表示）。
- **限制条件**（`restrictions`，复用挑战限制枚举，可选）：后续宇宙可加 `rate_div` 等；U3 起以 `rateMult` 温和削弱。
- **无限 New Game+**：`universes` 只显式定义 1–3（本版先行）；N>3 走 `fallback` 公式生成。碎片与结局线在固定周目收束，数字可无限延续。

## 4. 跨宇宙升级树（消耗奇点种子）

放在 `config/universes.json` 的 `crossUniverseUpgrades`，效果复用现有 `EFFECT_TYPES`。

| id | 名称 | 效果 | 成本（种子） | 前置 |
|---|---|---|---|---|
| `seed_engine_1` | 口袋引擎 I | 全产出 ×1e6 | 1 | — |
| `seed_rate_1` | 口袋时序 I | 时间速率 ×5 | 2 | — |
| `seed_crystal_1` | 口袋结晶 I | 穿梭晶体 ×2 | 2 | — |
| `seed_cap_1` | 口袋声张 I | 上限 ×1e10 | 3 | `seed_engine_1` |
| `seed_engine_2` | 口袋引擎 II | 全产出 ×1e10 | 5 | `seed_engine_1` |

- 已购列表存 `metaProgress.crossUniverseUpgrades`；效果在加载 / 跃迁后由 `singularity.applyCrossUniverse()` 重放。
- 成本与数值可用平衡模拟校准。

## 5. 引擎改动（小）

| 位置 | 改动 |
|---|---|
| `prestige.js` | `getUniverseCap()` 去掉硬编码 `FLOAT64_MAX`，改为 `min(baseCap × Π(cap_mult), Universe.getCapTarget())`；U1 的 target 即 float64 上限，保持 v0.4 不变 |
| `techs.js` | 第二阶段技术成本 × `Universe.getCostMultiplier()`（仅 phase=2）；新增 `resetAll()`（连永久技术一并清除，供宇宙跃迁用） |
| `universe.js`（新，低层状态） | 宇宙编号、奇点种子、跨宇宙升级 owned、按配置计算 cap/cost 乘子；无业务依赖，供 conditions / techs / prestige 读取，避免环 |
| `singularity.js`（新） | 跃迁编排：结算种子 → 快照 → 清空（资源/技术/时间/晶体/阶段2）→ 递增宇宙 → 重放跨宇宙与时间晶体升级 |
| `conditions.js` | 新增条件 `universe_ge`（宇宙编号 ≥ value） |
| `js/data/config.js` | 校验 `universes.json`；`CONDITION_TYPES` 注册 `universe_ge` |

**依赖方向**：`universe.js` 不 import 任何 sim 业务模块；`singularity.js` → resources/techs/prestige/upgrades/time/mults，无环。

- 宇宙编号与种子只在 `metaProgress` 存储；上限/成本乘子由配置与编号重新推导，不单独存档。
