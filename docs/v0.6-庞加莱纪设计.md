## 1. 数值锚点与红线

- 第三阶段驱动数值进入 eee 量级；核心锚点 **$10^{10^{10^{120}}}$（eee120）**。
- 红线（ADR-003）：v2.0 前一切数值不得超过 MegotaNum 上限（≈ $f_{\omega^2+1}$）。eee120 远在红线内（塔高 3），安全。

## 2. 箭头增速引擎（塔层）

第二阶段是**乘法**：`cap ← cap × 1e20`。乘法永远到不了塔高 3，所以第三阶段换成**迭代幂（塔层）**：每项技术把数值整体 `10^` 一次。

### 2.1 上限侧：`cap_tetrate`

```
getUniverseCap() = tower( min(baseCap × Π cap_mult, Universe.getCapTarget()), capArrows )

tower(x, n) = n ≤ 0 ? x : 10^(tower(x, n-1))      // 迭代实现：for i in 1..n: x = 10^x
```

- `capArrows` = 所有已研发 `cap_tetrate` 技术的层数之和（整数，通常每项 +1）。
- 起点仍是 `min(基准×乘子, 当前宇宙上限)`，因此**先继承 v0.5 的全部进度**，再在顶上叠塔。
- 叠塔顺序在 `min` 之后：宇宙上限目标只约束「塔基」，塔高把结果带过 eee。

### 2.2 产出侧：与上限挂钩（cap-link，修法 A）

若产出也走同阶 `10^` 叠塔，两者**不会保持比例**：设前上限 `B=10^b`、为在 τ₀ 秒内填满产出 `P₀≈B/τ₀`；各叠一层 `10^` 后
`log(prod)/log(cap) = 1/τ₀`，即 `prod ≈ cap^(1/τ₀) ≪ cap`，填塔时间天文级。故产出侧改用 **cap-link**：

```
上限资源产出下限 = 上限 / phase3.capLink.divisor     // 游戏秒；balance.json 默认 120
```

- 仅在**已叠至少一层 cap 塔**后生效（不影响第 9 宇宙原有节奏）。
- 只作用于上限资源（`balance.json: phase3.capLink.resource`，默认 `mass_energy`）；其余资源不挂钩。
- 成本用 `costFraction`：`cost = 当前上限 × costFraction`，每层游戏时间 ≈ `costFraction × divisor`，与塔高无关。
- 模拟与观察见 [docs/v0.6-平衡模拟.md](v0.6-平衡模拟.md)。

### 2.3 pacing：时间闸门（time-gate）

cap-link 在塔高 ≥2 时数值退化（`上限 / 常数 ≡ 上限`），无法给出 pacing。故真正的 pacing 改为**时间累积**：

- `phase3.cycleSeconds`（物理秒，默认 120）定义「一层塔」所需时间；
- `js/sim/cycle.js` 由 engine 每 tick 用 `dtReal` 推进循环，充满后 `cap_tetrate` 方可购买，买时归零；
- 结果：每层恒定 ≈ `cycleSeconds` 物理秒，与塔高 / 速率 / 数值精度无关（见平衡模拟：4 层 × 2min = 8.1min）。

### 2.4 为什么用共享箭头计数而非乘子

- 塔层是**整数迭代次数**，不是连续倍数；用整数计数最直观，也便于 UI 显示「当前塔高 N」。
- 与现有 `cap_mult` / `crystal_mult` 乘子容器解耦，避免把「乘」和「幂」混在一个乘积里。

## 3. 解锁（一次性）

- **触发**：`Universe.getUniverse() ≥ phase3.unlockUniverse`（`balance.json`，默认 **9**，即「第九口袋 · 舍入纪」之后）。
- **语义**：一次性解锁，写入 `metaProgress.phase3Unlocked`；主循环每 tick 检查（与第二阶段并列）。
- **与跃迁的关系**：本作跃迁会重置 `phase2Unlocked`（每个宇宙重新解锁第二阶段）。第三阶段同理在跃迁时置 false，但若 `universe ≥ 9` 成立，下一次 tick 立即重新解锁 → 对玩家表现为永久。
- **叙事**：舍入纪（指数百万）→ 庞加莱纪（幂塔/回归）。

## 4. 效果 / 条件类型（有限枚举扩展）

| 枚举 | 新增 | 作用 |
|---|---|---|
| `EFFECT_TYPES` | `cap_tetrate` | 上限塔层 +value（产出由 `phase3.capLink` 挂钩，见 §2.2） |
| `CONDITION_TYPES` | `phase3_unlocked` | 成就/碎片/挑战条件 |

- `techs.js` 的 `applyEffects` / `removeEffects` 处理两个新类型；`techs.reset*` 通过 `removeEffects` 自动清理。
- 阶段门控：`canBuy` / `buyTech` / `getAvailableTechIds` 对 `phase ≥ 3` 加 `isPhase3Unlocked()` 判断；`getCost` 对 `phase ≥ 2` 复用宇宙成本乘子缩放。
